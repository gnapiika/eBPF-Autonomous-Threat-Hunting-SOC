## 5. New Dashboard Panels

Five additional panels were implemented.

### 5.1 Security Events by Host

Purpose:

Visualize the number of security events generated by individual hosts.

ES|QL Query:

    FROM security-events
    | STATS event_count = COUNT(*) BY host
    | SORT event_count DESC

Visualization: Bar Chart

Observed results:

| Host | Events |
|---|---:|
| chetan | 3 |
| kali-lab | 1 |

### 5.2 Process Activity

Purpose:

Display security event counts grouped by process name.

ES|QL Query:

    FROM security-events
    | STATS event_count = COUNT(*) BY process_name
    | SORT event_count DESC

Visualization: Bar Chart

Observed results:

| Process | Event Count |
|---|---:|
| tee | 2 |
| suspicious-test-process | 1 |
| sh | 1 |

The X-axis was configured using `process_name`.

### 5.3 Security Events by Type

Purpose:

Visualize the distribution of security events according to their event types.

ES|QL Query:

    FROM security-events
    | STATS event_count = COUNT(*) BY event_type
    | SORT event_count DESC

Visualization: Pie Chart

This panel provides an overview of the distribution of event categories.

### 5.4 Process Investigation

Purpose:

Provide a detailed table for SOC analysts to investigate process-related security events.

ES|QL Query:

    FROM security-events
    | KEEP @timestamp, host, process_name, event_type, severity, message
    | SORT @timestamp DESC
    | LIMIT 10

Visualization: Table

The panel displays:

- Event timestamp
- Host
- Process name
- Event type
- Severity
- Event message

The Elasticsearch query was independently validated and returned four matching documents.

Grafana's Raw Data query mode was selected to display the returned records correctly.

### 5.5 Suspicious Process Monitoring

Purpose:

Filter selected security events for further investigation.

ES|QL Query:

    FROM security-events
    | WHERE severity == "high" OR process_name == "suspicious-test-process"
    | KEEP @timestamp, host, process_name, severity, event_type, message
    | SORT @timestamp DESC
    | LIMIT 20

Visualization: Table

This panel uses rule-based filtering to identify events requiring investigation.

Important:

The `suspicious-test-process` entry is a synthetic test event. Its presence does not establish that a real security threat or malicious process was detected.

## 7. Query Validation and Troubleshooting

During Process Activity and Process Investigation panel development, Grafana initially displayed a No data message.

The Query Inspector was used to investigate the issue.

Direct Elasticsearch ES|QL testing confirmed that:

- The index contained four documents.
- The requested fields were available.
- The time filter returned four documents.
- The Elasticsearch ES|QL query executed successfully.

The Process Activity visualization was corrected by configuring the appropriate X-axis field.

The Process Investigation panel was corrected by selecting Raw Data query mode instead of Metrics mode.

Both panels subsequently displayed the expected results.
